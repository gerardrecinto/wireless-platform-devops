What is in the repo

A small toolkit for the work that gets scattered across lab nodes.

1

Diagnose

sysperf watches per-core load, IRQ counts, memory and NUMA. netdiag reads bridges, routes, PCIe NIC counters and interface errors.

2

Package

rpm-tooling generates spec files for kernel images and PCIe drivers, and can verify RPMs and build YUM repo metadata.

3

Provision and ship

Ansible roles set up the base OS and container runtime. A Jenkins pipeline runs lint, tests, specs, images and deploys. Kubernetes manifests run the monitor with host networking.

Run it on a Linux host

python3 -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
pytest tests/ -v

sysperf --interval 2 --imbalance-threshold 25
netdiag --watch 10
rpm-tooling kernel-spec --kernel-version 6.1.80-rt27
ISOLATED_CPUS=4,5,6,7 sudo bash scripts/set_irq_affinity.sh
ansible-playbook -i ansible/inventory/hosts.ini ansible/provision.yml

The monitors are Linux-specific by design. They read /proc and /sys directly.

What this does not do
  • It is a toolkit, not a platform product. The repo says so.
  • This page cannot read a host. It runs the real analysis code on values you enter.
  • The 20M daily user figure in the README is a capacity target for design thinking. It is not a load test result.
  • It generates RPM specs. It does not ship built RPMs.
